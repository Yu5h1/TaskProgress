# 子項多選與批次複製參照

> Task ID: item-selection

## 用途

在預覽模式選取多個子項，一次複製它們的[參照](ItemReference.md)（一行一個），可以跨卡片。

## 操作

只在預覽模式有效；編輯模式沒有選取，進入編輯時清除選取。不保存：重新整理後選取消失，不寫入 report.json 或瀏覽器儲存。

| 裝置 | 操作 | 結果 |
|---|---|---|
| 滑鼠 | 點子項（不拖曳） | 只選這一項 |
| 滑鼠 | Ctrl／Cmd＋點 | 加選或取消這一項 |
| 滑鼠 | Shift＋點 | 從上次點的項目到這一項，依畫面順序，可跨卡片 |
| 滑鼠 | 點連結、按鈕、「更多」等控制 | 維持原功能，不改變選取 |
| 滑鼠 | 點子項以外的非控制區域 | 清除選取 |
| 鍵盤 | Tab 到子項 | 子項本身可聚焦（複製圖示不再是 Tab 停點） |
| 鍵盤 | ↑／↓ | 移動焦點，不改變選取 |
| 鍵盤 | Shift＋↑／↓ | 從起點延伸範圍 |
| 鍵盤 | Space | 加選或取消焦點所在的子項 |
| 鍵盤 | Ctrl／Cmd＋A | 選取畫面上所有可選子項 |
| 鍵盤 | Ctrl／Cmd＋C | 複製選取的參照；焦點項目不在選取內時只複製它 |
| 鍵盤 | Esc | 清除選取 |
| 鍵盤 | Alt＋↑／↓ | 仍是同級換位，不屬於選取 |

複製圖示：按在選取中的子項上，複製全部選取（提示寫「複製已選取的 N 項參照」）；按在未選取的子項上，只複製那一項。

觸控（長按進入選取模式）與手把（沿用鍵盤焦點模型，按鍵對應待定）尚未實作。

## 外觀

選取的子項以底色表示，平常透明：目前為 `--theme-accent` 的 28% 混色。UX 的 VisualFoundation 規定「選取」是 accent 底色配 onAccent 文字，但整列子項套滿 accent 是否太重尚待 UX Selection 規格決定，因此暫用淡化底色。鍵盤焦點另有 accent 外框。選取狀態另以只給輔助技術讀取的「已選取」文字表示，不只靠顏色。

## 結構

依「選取是可以掛到任何集合上的行為」拆成三層，方便之後換成 Web 共用元件：

| 層 | 檔案 | 責任 |
|---|---|---|
| 選取狀態 | `viewer/assets/selection-model.js` | 以穩定鍵記錄選取、範圍起點與焦點，不記位置；順序由宿主在需要時提供，所以多個集合（每張卡片一個）共用一份選取。不依賴框架，`subscribe` 符合 store 契約 |
| 輸入對應 | `viewer/assets/selection-input.js` | 把滑鼠與鍵盤轉成命令（單選、加選、範圍、移動焦點、清除、全選、複製）；裝置差異只在這層 |
| 宿主轉接 | `viewer/assets/item-selection.js` | TaskProgress 專屬：鍵是子項參照字串，順序是畫面上所有可選子項，複製時一行一個 |

Svelte 元件（`TaskList` → `TaskCard` → `ItemRow`）只傳遞並顯示這份選取，不持有選取邏輯。

## 之後的模組化方向

- **UX**：登記為候選規格 Selection（選取行為，屬集合層，可掛到任何集合）；裝置對應、長按與換位的衝突、選取外觀由該規格定案。本實作是「從實作收斂」的證據，見 UX `plan.md`〈尚未決定〉。
- **Web**：依 UX 規格提供共用的 Selection，取代本專案的前兩層；宿主轉接留在 TaskProgress。Web 的遷移對照為 `NativeUIAndDataUpdatePlan.md` 的 TP-9。
- 規格定版前，本專案改動選取行為時，三層的分界維持不變。

## 驗收

- Node：選取、加選、範圍、焦點移動、保留與清除；輸入對應；宿主轉接的複製順序與單項複製（`tests/item-selection.test.mjs`）。
- Browser：預覽模式點選、Ctrl 加選、Shift 跨卡片範圍、Shift＋↓、Space、Esc、點空白清除、Ctrl＋C 複製三項參照、選取底色與「已選取」標記。
