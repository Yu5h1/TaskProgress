# Report 與 Checklist 卡片收合

```text
TaskProgress
├─ Report TaskList → TaskCard／ReportPointerCard
├─ ChecklistApp → 工作項目卡 → checks
└─ 共用 CardDisclosure → 標題區、切換按鈕、可隱藏內容區
```

## 行為

每張頂層卡片在標題左側提供三角形切換：展開為 ▼，收合為 ▶；兩種清單均在「工作項目」旁提供單一全體收展圖示（上箭頭收合／下箭頭展開）。預設展開以保持現有閱讀方式；收合只隱藏詳細內容，保留標題、狀態與進度。Report 指路卡保留導航入口、載入／錯誤提示。

狀態由各清單以穩定 ID 保存於本次頁面生命週期；篩選、排序與資料儲存不重設，以 sessionStorage 按分頁與文件保存，重新載入還原收合狀態；儲存不可用時仍保留本頁記憶體操作。不寫入 report、checklist 或儲存歷史。共用控制只擁有顯示與無障礙語意，不擁有任務資料或寫入操作。

內容以 hidden 隱藏而非卸載，保留新增項目與其他輸入草稿。原生 button 提供鍵盤操作、aria-expanded 與 aria-controls。編輯、導覽與 checkbox 不以整張卡片點擊觸發收合。

全體圖示每次點擊只套用一次收展並清除先前單卡例外；之後各卡仍可獨立切換，不被全體狀態鎖住。

Checklist 下一步跳轉先展開目標工作項目，再恢復篩選與定位；收合卡片的進度統計以完整工作項目計算。

## 驗收

- Report 普通卡、指路卡與 Checklist 工作項目皆使用同一個收合控制。
- 單卡與全部切換可用；篩選／排序不遺失本頁的選擇。
- 收合保留標題／狀態／進度，指路卡導航與診斷仍可見。
- 收合／展開不產生資料儲存，草稿不因內容卸載丟失。
- 下一步跳轉可展開並聚焦被收合的 check。
- Browser、Desktop Checklist 與 Viewer 資產皆重建；實機鍵盤／窄螢幕／草稿驗收後排。

## 選取與換位

共用 CardList 擁有獨立單卡選取、拖曳落點與本機檢視排序，沿用既有 capsule-order 的 ID 正規化與搬移運算。所有排序模式皆可點擊卡片空白或文字區選取，顯示選取框；互動控制不改變選取。切換排序保留選取，拖曳結束也不清除。鍵盤聚焦卡片後 Enter／Space 選取、Escape 取消。僅自由排序模式可用滑鼠按住卡片空白處直接拖曳，不提供選取或上下移按鈕；文字、連結、checkbox 與編輯控制保留原操作。目標上半部／下半部分別插入之前／之後。自由排序模式下，鍵盤可 Tab 聚焦卡片後用 Alt＋↑／↓ 移動，移動後聚焦原卡。

工作項目旁單一排序圖示依序循環：順排（既有狀態排序）、逆排（反轉既有排序）、自由排序（手動順序）。順排圖示為向下箭頭與逐項縮短的橫條，逆排反向；自由排序為無箭頭、不等長橫條。切回順排即恢復既有排序，移除原「還原排序」文字按鈕；切換模式保留自由排序記憶，模式本身也按文件保存。篩選時只重排可見卡片的槽位，隱藏卡片留在原位置；新增 ID 接在自訂順序之後，刪除 ID 不再參與移動。選取及換位不呼叫資料儲存，不改變 ID、相依關係或 Checklist 下一步判斷。

Browser 以 report scope／report ID 或 Checklist scope／task／round 隔離 localStorage。無法儲存時提示只保留本頁。Desktop Checklist 尚未提供穩定完整檔案識別，因此只保留本頁順序，避免同名檔案共用設定。

驗收：空白處前後拖曳與鍵盤移動可用；篩選隱藏位置不變；重新載入 Browser 保留順序且跨文件隔離；三種排序切換有效，且僅自由排序能拖曳與鍵盤換位；資料不因換位儲存，草稿及收合狀態不變。

## 可見性控制

排序圖示右側提供點擊／長按選單，包含四個圖示：睜眼「啟用」依各卡 hidden 設定顯示；閉眼「全體關閉」暫時隱藏全部卡片且保留各卡設定；斜線眼「禁用」顯示所有符合篩選的卡片並隱藏單卡眼睛；「重置」清空所有 hidden 設定並回到啟用。預設禁用。

排序與可見性共用 [IconChoice](IconChoicePlan.md)，由該設計擁有浮動列定位與操作規則。不提供查看隱藏項目／套用隱藏按鈕，也不實作透明度或疊牌。

單卡眼睛在三角形與標題／完成框之間，只有啟用時顯示。隱藏保持元件掛載，不寫來源檔。Browser 按文件 key 在 sessionStorage 保存；Desktop 缺少 key 時僅本頁。下一步取消目標隱藏並展開；若全體關閉則先回啟用。只有自由排序可重排，隱藏槽位保持原位。

Desktop transport 提供既有 reset 協定，與 Browser 使用同一份清空實機結果 UI、確認框、草稿限制與失敗回報。
