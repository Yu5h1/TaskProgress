# CharacterBuilder A–F 跨平台協作檢討

```text
使用者
└─ 簡短訊號：請繼續 A／請驗收 A
   └─ 專案入口 → 已分派項目的唯一文件
      ├─ TaskProgress：項目、負責者、相依與階段
      ├─ checklist／負責文件：範圍、操作、驗收與固定交付路徑
      ├─ worktree：隔離程式與文件修改
      └─ 分派者：收件、合併、主線驗收與紀錄
```

## 問題與目標

2026-11-07，使用者要求在 CharacterBuilder A–F 全部通過後檢討：已有 TaskProgress，為何仍須反覆複製長指示及轉貼交付內容？當平台不能互相通知時，使用者應只需對已承接工作的 session 說「請繼續 A」「請驗收 A」，agent 即能依文件找到目標與下一步。

本文件記錄這輪檢討的證據、根因及落實建議。它不新增任務狀態來源，也不將建議冒充為已修改的共用規則。所屬卡片為 [同一 repo 的多 agent 平行執行](WorktreeReportPlan.md)；進度由該卡片的 Report 項目承擔。

## 根因

1. **沒有先把分派變成可接續的項目。** TaskProgress 已有 Report、checklist、認領及相依機制，這次卻先產生聊天指示，未建立可由 A–F 唯一定位的文件入口。這是分派方式的缺失，不能歸因於缺少通知 API。
2. **把通知與工作內容當成同一件事。** 平台不能互傳訊息，只代表使用者需要傳遞啟動訊號；任務內容、交付位置與返工條件仍可先寫入共享文件。
3. **沒有固定所有交付的收件位置。** 唯讀調查也會產生需要他驗的成果。C 的「只回覆、不落檔」讓主線無法按文件收件。
4. **沒有用階段區分分支交付與主線驗證。** 隔離測試、文件審查、合併及主線畫面驗收各有完成條件。A 的畫面驗收必須等主線載入正確版本，不能靠 worktree 中的樣式或文件推定完成。
5. **既有流程在平台能力不同時缺少接續說明。** 共用 `task-progress` 的〈Queues and sessions〉已定義分派者及主線紀錄，但不能啟動其他平台 session 時的簡短人工訊號與文件接續路徑沒有在這次分派落實。user-level entry 也限定明確 invocation 才啟動整個 task-progress 流程；不能以此為理由讓普通已分派工作只留在聊天，也不應暗中啟動整個隊列。

## 落實建議

### 分派前先寫入既有文件

先建立或沿用正式項目與 checklist／負責文件，再交給其他 session。文件帶上目標、Paths、Needs、驗收條件、worktree／分支、固定交付位置及目前階段；詳細設計仍由原負責文件擁有。A–F 是該輪的簡稱，專案入口只將簡稱路由到唯一項目，不另抄完整工作內容。

### 使用者只傳訊號

在已知專案與分派輪次內，「請繼續 A」讀取同一項目的當前狀態並處理下一個未完成步驟；「請驗收 A」讀取該項目的原始要求、交付提交及驗收紀錄。只有簡稱無法唯一解析、文件缺漏或他人修改衝突時才詢問，並指出確切缺口。這是既有分派項目的接續，不等於未經要求啟動整個 scope 的隊列。

### 完成與返工回到原項目

每項工作都有固定交付檔或文件中的固定章節，唯讀調查也一樣。完成回報只需項目、提交與驗證結果；返工寫回原項目的未通過條件，由原 session 讀取，不再產生另一份長 prompt 作為唯一入口。

### 分派者負責收件與主線階段

分支交付、定向驗收、合併及主線畫面驗收分開記錄。工作已足以進入下一階段時，分派者依既有授權接續處理，不等待使用者再次搬運相同指示。共用服務、port 與正式 Report 仍由唯一負責者協調。

## 建議的落實位置與驗證

- `.agents/skills/agent-work-route/SKILL.md`：一般分派與接手先確立文件入口；簡短人工訊號足以接續已分派工作。
- `TaskProgress/.agents/skills/task-progress/SKILL.md` 的〈Resolve the target〉、〈Queues and sessions〉：確認簡稱定位及無法互傳通知時的接續方式，保留明確 invocation 才啟動整個流程的邊界。
- `TaskProgress/.agents/skills/task-progress-report/SKILL.md`：項目階段、交付路由與主線紀錄沿用既有欄位，不新增第二份狀態檔。
- 專案 handoff／項目文件：實際保存那一輪的路由與交付位置，不把 CharacterBuilder 的 A–F 寫成全域固定任務。

落實後，以三個不同上下文的 session 分別接收「請繼續 A」「請驗收 A」及一個唯讀調查完成訊號：都能從共享文件找到唯一目標、交付與應執行階段；返工仍回到同一項目；使用者無須轉貼完整指示或回報全文。若有歧義，應列出候選及缺失的專案／輪次，不能猜測。
