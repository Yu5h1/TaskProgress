- **Legacy→envelope read-time adapter implemented (2026-08-25).** Closes the gap the architecture plan had left open: manifest `source` points at the existing flat Draft 0.2 `time.analysis.json`, which carries none of the common envelope's root fields. User-chosen direction was read-time adaptation — the analyzer, the file on disk, and public reports are all untouched. New `viewer/assets/time-envelope-adapter.js` (`adaptLegacyTimeAnalysis(legacy, {moduleId})` → `{envelope, provenance}`; pure transform, no I/O/DOM/clock, asserted by test) plus `tests/time-envelope-adapter.test.mjs` (22 tests). Three design constraints are enforced by tests, not just documented: (a) **`report_id` is never manufactured** — envelope validation exists to compare sidecar identity against the report, so a value copied from the comparison target would make that check tautological; the envelope omits it and declares `identityBinding: "scope-only"`; (b) **`as_of` is not silently promoted to `generated_at`, `method` is not promoted to `generator`** — the first pair genuinely differ under `analyze --as-of`, the second would erase the difference between changing tool and changing algorithm; `as_of`/`method` stay authoritative inside `data`, `generator` honestly names the adapter; (c) **provenance rides alongside the envelope, not inside it**, so a migration-period concern doesn't permanently widen the contract every module must satisfy. Required one change in `module-model.js`: `validateModuleEnvelope` gained an `identityBinding` option (`IDENTITY_BINDINGS = ["full", "scope-only"]`, default `full`), where `scope-only` requires `report_id` to be **absent** rather than merely unchecked — so the relaxed mode cannot be used to smuggle in an unverified value — and an unknown binding throws instead of silently relaxing. Implementation corrected the design doc on one point: `data` must be the legacy document **verbatim**, including the `schema_version`/`scope_id` also lifted to envelope roots, because `inspectTimeAnalysis` reads both and stripping them would leave `data` unvalidatable by the one validator built for it. Verified against the real on-disk `time.analysis.json` + `report.json`: envelope validates clean under scope-only, freshness correctly reports `freshness_unknown`, the Time domain validator still accepts `data`, and `data` is byte-identical to the source. ## Standing project rule

- **One UI source (2026-08-05, user decision).** A screen element visible in more than one place may have only one implementation. Outranks feature work, parity patching, and further migration. ## Architecture and contracts (current, load-bearing)

- **UI host boundary:** `viewer/assets/ui-host.js` — `registerUiAdapter`, `useUiAdapter`, `createUiView(region, target, props)` returning `update`/`destroy`. Only plain data and callbacks cross; the host never touches rendered nodes (`tests/ui-host.test.mjs` asserts the source has no DOM access, no framework name). One adapter active at a time — registering a second does not take over. Bundling `ui-host.js` into the preview bundle instead of keeping it external gives the bundle its own adapter registry, so registration silently misses the instance `app.js` imports (zero cards, no error) — `rollupOptions.external` + `output.paths` must keep it external.
- **Regions are named:** an adapter declares which regions it implements; mounting an unclaimed region throws. Current Svelte adapter (`viewer-adapter.svelte.js`) covers `task-list`, `status-overview`, `status-filters`, `project-progress`, `mode-toggle`, `save-bar`, `add-control`, `diagnostics`, `scope-directory`, `theme-control`, `time-summary-button`, `time-dialog`, `report-summary`, `delivery-save-confirmation`. (`time-settings` and `delivery-risk-preview` were retired as separate regions 2026-08-24 — both render inside `time-dialog` now.) **The committed bundle (`viewer/assets/viewer-ui.js`) is a separate artifact from this source file** — registering a region in `viewer-adapter.svelte.js` does nothing for the production Viewer until `npm run viewer:ui:build` regenerates the bundle; the adapter throws `不支援 region「...」` at runtime otherwise, and nothing in the test suite catches it (tests read sources, not the bundle — see Blockers).
- **Architecture boundary:** `editor-core/` + `ui-components/` + `local-service/` — one component set serves both preview and edit; mode only decides whether a field is editable, like an `InputField` toggling `editable`. Public deployments stay read-only through build-time splitting (packaging), not a second implementation (architecture). Edit-only affordances (delete, save bar, add controls) are states of the shared component, not a second interface.
- **Editor presentation layering:** `viewer/assets/editor-presentation.css` is the shared **geometry** contract, colour-free by contract (`tests/editor-presentation.test.mjs` asserts no `color`/`background`/`box-shadow`). `viewer/assets/styles.css` is the shared **theme** stylesheet (the Svelte bundle imports it via `@editor/styles.css`); cross-host colour rules key on the shared class. - **Svelte component boundary:** `App.svelte`, `TaskCard.svelte`, `ItemRow.svelte`, `ThemeControl.svelte`, `TimeSummaryButton.svelte`, `TimeDialog.svelte` must not reference `localStorage` (asserted by `tests/svelte-editor-spike.test.mjs` and `tests/theme-model.test.mjs`). - **Time dialog architecture:** `viewer/assets/time-dialog-control.js` is the framework-neutral controller (`snapshot()`, `openProjectDetail()`, `closeDialog()`, `toggleDetails()`, `setActiveTab()`, `submitCapacityForm()`, plus `itemTime`/`taskDuration`/`showItemTime`/`prepareSave`/`refresh`/`setEditing`/`setReportStructureStale`) — no DOM, every view returns plain data. `activeTab`/`detailsExpanded` are one shared pair across the project and item dialogs; opening an item dialog does not reset either. The capacity quick-editor's visibility is tied to the same global `setEditing()` call edit-mode entry/exit already makes (see Ruled-out directions). `refresh()` must run once at construction, not only on the timers — the summary button otherwise shows whatever urgency was baked into the sidecar file at generation time until the next 60-second tick.
- Two Svelte gotchas specific to how this project mounts components imperatively (`mount(Component, {props: someExternalState})`, the pattern every `ui-host.js` region uses):
  1. A bare `$:` block, or an action's `update(prop)` parameter, reading a legacy `export let` prop re-evaluates once after mount and then silently stops seeing further changes — even though the same prop keeps driving ordinary template expressions (`{title}`, `{#if kind==="item"}`) correctly. Fix: make the dependent DOM structural (`{#if open}<dialog use:openOnMount>`) instead of imperative, since Svelte's own block (dis)connection is driven by the template reactivity that already works.
  2. A template call expression hides what it reads — `class={dropClass(filter)}` never re-ran when a handler set `dropTarget` elsewhere. Pass reactive state as an argument (`dropClass(filter, dropTarget)`) to make the dependency visible to the compiler.
  3. A `<select>` bound with `value={...}` is uncontrolled — the reader's own selection never reaches component state, so a cancel handler that reassigns the same prop is a no-op. Use `bind:value`.
  4. Legacy `$:` statements are pre-effects, not lazy deriveds, so anything persisted on an event must be recomputed from source state at commit time, not read from an already-rendered derived value that may not have run yet in the same task.
- **Browser cache trap:** `viewer/assets/viewer-ui.js` has a stable filename with no cache-busting query, so a rebuilt bundle can keep serving from cache through a forced reload. `performance.getEntriesByType("resource")[...].transferSize === 0` is the tell; serving on a fresh port is the fastest fix.
- **Bundle staleness CI guard:** `notify-docs.yml`'s `verify-bundle` job runs `npm ci`, rebuilds with `npm run viewer:ui:build`, fails if `git diff` shows the bundle changed, then runs the suite; `notify` depends on it. Trigger paths include `experiments/editor-svelte-spike/**`, `package.json`, `package-lock.json`. Unproven in CI per Blockers above.
- **Preview bundle must stay flat** at `viewer/assets/viewer-ui.js`: the docs Pages artifact copies `viewer/index.html` + `viewer/assets/`, and a subdirectory only survives if that copy is recursive (unverifiable from this repo). Vite's `outDir` is `viewer/assets` with `emptyOutDir: false` (`true` would delete hand-written sources). A missing bundle degrades to a fatal error screen, not a silently broken page — `createUiView` throws with no adapter registered.

## Report/workspace model

- The same report schema can describe a multi-project workspace, a project, or a narrower component. Viewer/Launcher render one selected scope and do not infer hierarchy; report-generation resolves hierarchy from the target scope, its `tasks.md`, canonical routes, and child reports/handoffs.
- A workspace report is a curated portfolio view — it may mix direct tasks, whole child scopes, and selected child deliverables, but must not recursively scan directories or treat unrelated child items as equal-weight. A workspace scope may validly have no handoff of its own.
- Cross-scope drill-down now has an approved design that nothing implements yet: `plan.md#report-指路任務卡與單層-scope-導航` (approved 2026-08-18). A pointer card stores only `id`, `title` and `report_ref.scope_id`; everything shown is derived from the target report at read time, one level deep. Deterministic aggregation beyond that one level, and stale-roll-up detection, remain unprovided by the Viewer, Launcher and schemas.
